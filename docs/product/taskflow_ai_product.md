# TaskFlow AI: Описание Продукта И Feature Taxonomy

`TaskFlow AI` - вымышленный B2B SaaS для управления задачами, проектами и командной работой. Продукт используется продуктовыми командами, project managers, разработчиками и support-командами, чтобы планировать работу, отслеживать риски, автоматизировать уведомления и анализировать качество процессов.

Этот документ задает единый продуктовый контекст для RAG-датасета. Все технические документы, support tickets, отзывы, метрики и тестовые вопросы должны ссылаться на одни и те же фичи, чтобы ассистент мог связывать данные между слоями.

## Основной Сценарий

Компания использует `TaskFlow AI`, чтобы:

- вести проекты и задачи;
- планировать спринты;
- назначать ответственных;
- настраивать роли и права доступа;
- импортировать задачи из CSV;
- получать уведомления в Slack, Telegram и email;
- искать задачи и обсуждения;
- строить отчеты по delivery, SLA и качеству работы;
- интегрироваться с внешними системами через webhooks.

## Целевые Пользователи

### Product Owner

Интересуется бизнес-влиянием проблем и приоритетами развития продукта.

Типовые вопросы:

- какие фичи сильнее всего влияют на NPS;
- какие проблемы повышают churn risk;
- что стоит исправить в следующем релизе;
- какие жалобы связаны с падением adoption;
- какие технические ограничения мешают продуктовой метрике.

### Project Manager

Интересуется сроками, зависимостями, рисками и ресурсами.

Типовые вопросы:

- какие риски есть у релиза;
- какие команды или фичи блокируют delivery;
- где растет backlog;
- какие проблемы требуют координации между командами;
- какие изменения стоит вынести в отдельный milestone.

### Developer

Интересуется техническими деталями, API, endpoint, payload, ошибками и ограничениями.

Типовые вопросы:

- какой endpoint отвечает за конкретную функцию;
- какие ошибки возвращает API;
- как устроены webhooks;
- какие поля обязательны в payload;
- какие технические документы описывают проблему.

### Support Manager

Интересуется частыми жалобами, SLA, категориями тикетов и готовыми рекомендациями для support-команды.

Типовые вопросы:

- какие жалобы повторяются чаще всего;
- какие категории тикетов растут;
- какие проблемы ухудшают satisfaction;
- какой macro-ответ можно подготовить;
- какие фичи требуют обновления help center.

## Feature Taxonomy

### `tasks`

Базовая сущность продукта. Задачи имеют статус, приоритет, исполнителя, сроки, комментарии, вложения и историю изменений.

Связанные темы:

- создание и редактирование задач;
- bulk update;
- статусы задач;
- просроченные задачи;
- история изменений.

### `projects`

Группировка задач по продукту, команде или инициативе.

Связанные темы:

- project dashboard;
- project health;
- owners;
- project-level permissions;
- архивирование проектов.

### `sprints`

Планирование работы по итерациям.

Связанные темы:

- sprint planning;
- capacity;
- velocity;
- blockers;
- перенос задач между спринтами.

### `notifications`

Уведомления о задачах, комментариях, изменениях статуса и SLA.

Связанные темы:

- Slack notifications;
- Telegram notifications;
- email notifications;
- задержки уведомлений;
- настройки частоты;
- повторная отправка.

### `permissions`

Роли и права доступа.

Связанные темы:

- роли `admin`, `manager`, `developer`, `viewer`;
- доступ к проектам;
- доступ к отчетам;
- audit log;
- ошибки доступа.

### `csv_import`

Импорт задач и проектов из CSV.

Связанные темы:

- mapping колонок;
- validation errors;
- partial import;
- rollback;
- duplicate detection.

### `search`

Поиск по задачам, комментариям, проектам и пользователям.

Связанные темы:

- full-text search;
- фильтры;
- поиск по assignee;
- поиск по due date;
- задержка индексации.

### `reports`

Отчеты для PO, PM и руководителей.

Связанные темы:

- delivery report;
- SLA report;
- NPS impact report;
- adoption report;
- export to CSV/PDF.

### `webhooks`

Интеграция с внешними системами.

Связанные темы:

- webhook delivery;
- retry policy;
- signature validation;
- failed deliveries;
- payload schema.

### `integrations`

Интеграции со Slack, Telegram, GitHub, GitLab и email.

Связанные темы:

- подключение workspace;
- OAuth;
- bot permissions;
- sync errors;
- rate limits.

## Связи Между Фичами

| Feature | Частые Связи | Почему Важно Для RAG |
| --- | --- | --- |
| `notifications` | `integrations`, `webhooks`, `permissions` | Жалобы на уведомления часто требуют техдоков по integrations и метрик по SLA. |
| `csv_import` | `tasks`, `permissions`, `reports` | Ошибки импорта влияют на создание задач, доступы и корректность отчетов. |
| `reports` | `projects`, `sprints`, `permissions` | PO и PM задают бизнес-вопросы, но ответ зависит от данных проектов и ролей. |
| `search` | `tasks`, `projects`, `comments` | Жалобы на поиск требуют связи между user feedback и техническими ограничениями индексации. |
| `webhooks` | `integrations`, `notifications` | Developer-вопросы часто пересекаются с support-жалобами на недоставленные события. |

## Seed Data Principles

Все документы для RAG должны соблюдать правила:

- каждый документ указывает одну или несколько `feature`;
- отзывы и тикеты должны ссылаться на реальные фичи из taxonomy;
- метрики должны быть связаны с теми же фичами, что и жалобы;
- технические документы должны объяснять хотя бы часть проблем из support/user feedback;
- тестовые вопросы должны проверять связи между слоями, а не только поиск по одному документу.

## Примеры Связанных Сценариев

### Сценарий 1: Проблемы С Уведомлениями

- Support tickets: пользователи жалуются, что Slack-уведомления приходят с задержкой.
- Metrics: adoption `notifications` падает, average resolution time растет.
- Tech docs: описывают retry policy и rate limits Slack integration.
- PO-вопрос: "Как задержки уведомлений влияют на удержание клиентов?"
- Developer-вопрос: "Где описан retry mechanism для Slack notifications?"

### Сценарий 2: Ошибки CSV Import

- Support tickets: пользователи получают validation errors при импорте задач.
- Metrics: растет количество failed imports и tickets по `csv_import`.
- Tech docs: описывают mapping колонок и duplicate detection.
- PM-вопрос: "Какие риски у релиза CSV import v2?"
- Support-вопрос: "Какой macro-ответ подготовить для ошибок импорта?"

### Сценарий 3: Права Доступа К Отчетам

- Support tickets: менеджеры не видят отчеты по проекту.
- Metrics: падает adoption `reports` в enterprise-сегменте.
- Tech docs: описывают `project_admin` и `viewer` permissions.
- PO-вопрос: "Стоит ли приоритизировать исправление доступа к отчетам?"
- Developer-вопрос: "Какие роли имеют доступ к SLA report?"
